    工作原理

    你要的是结果，不是待办清单

    1

    告诉它你要的结果

    "准备一份客户简报"、"理一下我的日程"、"看看发布在 Jira 和 GitHub 上的进度"。用一句话描述目标即可。

    2

    蜂群拆解计划、并行干活

    任务被拆成步骤 DAG，多个 worker 在你的桌面、文件和已连接的应用之间同时工作，进度实时可见。

    3

    关键动作先问你

    发消息、改日程、执行命令——有后果的操作都会先弹出批准门，由你拍板或改向。

    4

    拿到的是成品

    一份精修过的文档、一条带数据的回复、一次更新好的日程、一封整理好的邮件——落地为能打开、能分享的文件。

    蜂群协同

    看得见的蜂群，管得住的团队

    不是把任务切碎了扔进黑盒并行——planner、executor、reviewer 各司其职，治理回路全程盯着。过程可暂停、可干预、可回放。

    一次蜂群运行 · "市场分析报告"

    把鼠标放到任意节点上，看这个 worker 在想什么。提示：过程不是黑盒——每个 worker 的思维链与耗时都实时可见、可暂停。

    循环粘度 Loop Viscosity
    0.18越低越顺

    衡量蜂群是否在空转打结：卡壳、互相等待、重复返工都会推高它。

    漂移度 Drift Score
    0.07越低越稳

    执行是否偏离计划与目标。漂移超阈值自动回滚（REVERT）或暂停（PAUSE）。

    安全红线 Red Lines
    0命中

    触线即停：蜂群自动冻结并升级给你（ESCALATE），配合收件箱审批流处理。

    ※ 示意数据，用于说明治理维度。每次运行都会生成完整快照，可复盘、可追责。

    它做什么

    从一个任务开始

    三个真实场景，来自产品开箱即带的快速开始任务——注意每一次"离开你的机器"的动作，都先经过你批准。

    分析一个目录的文件

    "分析这个文件夹里的文件，总结哪些事重要。"
    6 steps本地文件夹

    读完目录里的全部文档，交叉比对后给出摘要：哪些在等你拍板、哪些已经过期、哪些可以归档。

    摘要报告.md已交付 · 在你的工作区里
    没有需要批准的操作——全程只读你的文件夹
    数据流向：不离开你的机器

    从 HubSpot 线索生成报告

    "就我最近的 HubSpot 线索做一份报告：来源、阶段、谁需要跟进。"
    8 stepsHubSpot本地文件

    拉取近期线索，按来源与销售阶段分组，算出转化漏斗，圈出超过 7 天没跟进的高价值名单。

    线索报告.md + 图表已交付
    把报告发给销售负责人？
    离开你的机器 → Email · 发送前确认

    GitHub → Slack 每周自动化周报

    "设一个每周进度汇报：汇总我 GitHub 仓库的活动，每周五早上发到 Slack。"
    自动化 · 每周五 09:00GitHubSlack

    面向重复工作的定时自动化：每周五早上汇总仓库动态、合并请求与阻塞项，成稿后投递到频道。

    本地优先

    数据在你手里，模型随你换

    agent 循环、对话、连接器 token、模型 Key 全部存在你机器的本地 secret store 里。唯一的云组件，是连接器 OAuth 握手的一个小服务。

    技能与资产

    越用越厚的团队资产

    蜂群把重复性工作沉淀为可复用资产：技能、知识、模板。单机已经可用，团队工作区在路上。

    一次协同跑通→ 沉淀为模板 / SOP→ 团队复用→ 资产增值↺
    🧩

    技能市场

    把重复性工作写成 SKILL.md 技能：创建、编辑、zip 导入导出、安装数与评分统计。蜂群在对话里就能创建技能。

    📚

    知识文件库

    工作区文档自动索引 + 本地文件夹导入 + 手动条目，分块向量化检索，中文开箱即用——蜂群与对话都能直接查。

    🐝

    蜂群模板

    把一次跑通的协同——分解策略、技能组合、验收标准——整体存档。下次同类任务直接套用团队的成熟打法。

    ※ "员工走了，资产留下；工具换了，流程留下。"——资产始终可本地导出，不绑定任何云厂商。
