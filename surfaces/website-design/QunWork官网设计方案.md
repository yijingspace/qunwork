## 〇、执行摘要

**一句话结论：QunWork 官网不应该把自己展示成"又一个 AI 助手"，而应该把产品最大的差异化——"看得见、可干预、可沉淀的多智能体蜂群"——做成官网的第一视觉与第一叙事。**

三个关键设计判断：

1. **主视觉是蜂群，不是聊天框。** 竞品官网的 hero 要么是"输入框 + 任务 chips"（Manus），要么是"产品情景卡片流"（OpenWorker）。QunWork 的独特资产是 SwarmView（planner→executor→reviewer→governance 的 DAG 实时可视化），官网 hero 应直接呈现"一次蜂群运行"的动态画面：目标进来 → 任务 DAG 展开 → 校验收敛 → 交付物落盘。这既是产品截图，又是产品证明。
2. **信任是转化路径的主干。** 本地优先、审批门、可审计是 QunWork 区别于云端全家桶（WorkBuddy/Coze/Manus）的底座，也是企业采购的第一问（"出错了怎么办"）。官网必须有独立的安全与治理章节，并把"批准/拒绝"交互做成可视组件，而不只是一句口号。
3. **双语双市场，中文主场。** 产品已是中英双语（i18n 完整），官网以中文为主语言、英文为对照，品牌词"群沃客"与"蜂群"语汇贯穿；开源（MIT）与上游致谢（OpenWorker / Andrew Ng / aisuite）必须显性呈现——这既是合规（NOTICE.md），也是开发者社区的信任入口。

## 二、输入依据（事实清单，防止方案漂移）

以下事实全部来自本机产品仓库与官网实测，是本方案的地基：

**产品事实（来自 `E:\QunWork\QunWork` 仓库）**

- 定位原文："让 AI 帮你把日常任务做完……交付**成品**而不只是聊天"（README）；愿景为"多 Agent 协同、蜂群智能"。
- 能力清单：蜂群协同（Orchestrator：planner→executor 并行→reviewer 校验→治理回路，进度/思维链/历史实时可见）、技能市场（SKILL.md 创建/导入导出/评分统计）、知识文件库（自动索引+向量化检索）、25+ 集成（GitHub/Slack/Jira/Notion/Linear/HubSpot/Outlook/monday/Gmail/Google Calendar 等）+ 任意 MCP 工具、按计划运行（晨报/周报/定时自动化）、行动前先询问（批准门控，无人值守时待确认事项进收件箱）。

**蜂群协同能力复核（2026-09-13 逐条对代码，v1.0 方案写此章时的 3 项缺口已补齐）**

- **三泳道运行图**（`surfaces/gui/src/components/SwarmView.tsx`）：规划 / 并行执行 / 校验收敛三列；任务节点按依赖拓扑排序、状态着色（done/running/pending/needs_human），依赖与汇聚连线；**hover/聚焦/点击节点**展开该 worker 的思维链节选、执行 agent、置信度与依赖 —— 即 v1.0 想要的"节点 hover 思维链"，已是产品内真实交互。
- **运行回放**：快照携带完整有序事件日志，产品用与实时视图**同一套归约逻辑**折叠事件前缀，可拖拽进度条逐帧重演一次运行（▶/⏸/■ + 帧计数）。是真实回放，不是重演动画。
- **治理遥测（四枚，全部真实产出）**：`Governance.inspect()` 每次检查计算 **循环粘度 viscosity**、**漂移度 drift**、**自主率 autonomy**（无需返工即通过的步骤占比）、步数；阈值随事件下发（`viscosity_mid 0.4 / viscosity_high 0.66 / drift 0.8`），前端不再硬编码；UI 已渲染为指标卡（含 warn/stop 标记与逐步走势）。
- **安全红线是布尔跳闸**：关键词命中（如 `drop table` / `rm -rf /`）→ PAUSE + escalate，并带 `red_line` 显式标志；它**没有数值形态**，对外应表述为状态徽章（未触发 / 已跳闸）。
- **治理动作**：NOP / WARN / REVERT（把已完成任务打回重跑，含重试预算重置）/ PAUSE / ESCALATE，全部写入持久化审计（可追溯的安全干预）。
- **命令甲板**：暂停/恢复 · 向运行中的蜂群注入操作员消息 · fork 子任务并入实时计划 · 任务改派到其他 agent · reviewer 驳回后的 requeue 审批。
- **QunMesh 蜂群网格**（`coworker/orchestrator/mesh.py`）：四信道信息素（StigmergyBus）驱动的动态批量领取，`mesh_claim` / `mesh_domains` / `mesh_topology` 事件随运行实时下发；无信息素、单任务、任务同属一个 agent 时逐级退化安全。**v1.0 方案完全未提及这一层。**
- **7×24 长程遥测**：LoopCoop 收敛曲线（谱隙 / 理论轮数 / 收敛过程）与分形降级轨迹随 run 快照持久化，产品内已有曲线与轨迹可视化组件。
- **决策回放时间轴**（13 影子模式）：每个 worker 的工具选择/权限/scope/审批落成可拖动回放的决策轨迹，蜂群与主会话共用同一组件 —— 比"审批门"更硬的合规证据。
- **组织资产沉淀**：蜂群经验 lessons（按 workspace 隔离、可筛选删除）/ 任务模板（把"分解策略+验收标准"整体存档）/ 协同报告；run 支持 fork 分支 A/B 对比（`parent_run_id`）与 Dissolve 任务组生命周期。
- **协同报告与脱敏导出**：报告含计划表、逐任务评审与置信度、尝试次数、思维链节选、产出节选与治理表（含指标列）；**可一键导出脱敏样例** —— workspace 路径、家目录、邮箱、URL 凭据、疑似密钥（`sk-`/`xoxb-`/`ghp_`/`AKIA` 等）全部打码，另存为 `coordination-report-<run>-redacted.md`。这正好补上 /swarm 页"协同报告样例（脱敏）"的取材来源。
- 模型自由：OpenAI/Anthropic/Gemini/Inkling/GLM(Z.ai)/DeepSeek/Kimi/Qwen/MiniMax/Mistral/Grok 共 11 家云供应商，+Together/Fireworks 开源权重，+Ollama 完全本地；不锁定模型。
- 本地优先：agent 循环、对话、连接器 token、模型 Key 全部在本机 secret store；唯一云组件是连接器 OAuth 握手代理；服务默认只监听 127.0.0.1 并自签一次性 token。
- 形态：Tauri 桌面应用（Windows NSIS/MSI 与 macOS DMG 已有 0.22.x 构建产物）+ 浏览器 UI；MIT 开源，OpenWorker 二次开发分支。
- 官方产品语料（`i18n/messages.ts`）："有什么任务需要我帮你解决？"／"告诉我你需要解决什么——我会规划、执行并保存结果。"／"多智能体蜂群"／"蜂群运行中…"／"从一个任务开始"／"把待批准项发送到收件箱"。

**品牌事实（来自 `surfaces/gui/src/styles.css` 与 assets）**

- 一句话定位："唯一一个把多智能体协同做成**可治理、可沉淀、可审计的团队**的本地优先工作操作系统。"
- 对外叙事三句话（企业销售话术，官网可直接引用）：对 IT/安全——"数据不出公司，本地部署，审计完备"；对业务负责人——"AI 团队的 SOP 沉淀在你公司，不绑定任何云厂商"；对老板——"员工走了，资产留下；工具换了，流程留下。"

## 三、品牌定位与叙事

### 3.1 官网主叙事（Hero 候选与定稿）

| 候选 | 评估 |
|---|---|
| "让 AI 帮你把日常任务做完。"（README 原文） | 准确但平，任何助手都能说 |
| "不止回答，交付成品。" | 突出交付物，但丢失"群"差异 |
| **"一份任务，一群 AI 同事，交付成品。"** | 同时覆盖：任务制（非聊天）、蜂群（差异）、成品（结果）。**定稿** |
| 英文对照 | "One task. A swarm of AI coworkers. Real deliverables." |

**副标（定稿）**：QunWork 群沃客是常驻你桌面的开源 AI 同事团队：规划、并行执行、交叉校验，把复杂任务做成能直接用的文档、报表和自动化——全程跑在你自己的机器上，关键动作先征得你同意。

### 3.2 叙事三大支柱（对应官网三个核心区块）

1. **蜂群协同（Swarm）**——不是"多 Agent 并行"黑盒加速器，而是 planner/executor/reviewer 分工 + 治理回路 + 共享记忆的**透明团队**。官网证据：DAG 动画、进度/思维链可见、运行历史回放。
2. **本地优先（Local-first）**——数据与 Key 不出你的机器，模型随便换（11 家 + Ollama 完全本地）。官网证据：架构图（桌面壳/本地服务/你的文件·工具·模型）、"唯一云组件是 OAuth 握手"的诚实表述。
3. **可治理可沉淀（Governed & Compounding）**——审批门、运行快照可审计；技能、SOP、模板、知识越用越厚，形成组织资产。官网证据：批准卡组件、"存为团队模板"、资产清单视图。

### 3.3 官方语料词表（写作时对齐产品内文案）

| 用 | 不用 | 依据 |
|---|---|---|
| 任务（不是"对话/提问"） | 聊天、问答 | 产品以任务为单位 |
| 蜂群（swarm）／多智能体蜂群 | 集群、多线程 | 产品内固定译名 |
| 成品／交付物（不是"结果输出"） | 生成内容 | README 用词 |
| 收件箱（Inbox）待批准项 | 审核队列 | 产品面板名 |
| 技能（Skills） | 插件、插件包 | 产品面板名 |
| 知识文件库 | 向量数据库 | 面板名，避免技术黑话 |
| 连接器（Connectors） | 集成、API | 产品用语 |
| 你（第二人称，中文不用"您"保持产品一致） | 用户 | 产品内文案均用"你" |

**禁用**：无限制自主执行暗示（"全自动无人值守随便干"）；贬损竞品（对比页只列事实维度）；"颠覆/革命/吊打"。

## 四、竞品官网设计模式分析

### 4.1 逐家拆解

**OpenWorker（openworker.com，上游）——最直接的对标与基线**
- 结构：极简导航（Security/Coworkers/How it works/FAQ/Source/Download）→ hero（一句话价值主张 + 双平台下载 + 3 条徽章）→ 5 张任务情景长卡。
- 情景卡是灵魂：每张 = 真实任务 prompt + 步骤进度（"8 steps"）+ 中间结论 + **审批门组件**（"把 diff 开成 PR？Leaves this Mac → GitHub · Approve / Not now"）+ 产物预览（md/diff/图表）。它把"信任"做成了可看见的交互，而不是口号。
- 可借鉴：情景卡结构、审批门可视化、"Leaves this Mac →" 数据流向标注、下载直连 hero。
- 需规避：QunWork 有上游没有的**蜂群 DAG 与治理叙事**，不能照抄单 Agent 情景；中文市场需要更重的"本地优先/数据主权"表达。

**Claude（claude.com）——品牌权威型**
- 超大多级导航（产品/模型/方案/资源全展开）、定价与 FAQ 直接上首页、桌面下载常驻导航。
- 可借鉴：FAQ 结构（是什么/用来干什么/多少钱三问式）、多级导航的信息分组方式。
- 需规避：体量——QunWork P0 只有 1 个产品 1 个下载动作，不需要模型矩阵与方案页森林。

**Manus（manus.im）——任务入口型**
- hero 是"What can I do for you?" + 任务 chips（做 slides/建站/设计/游戏），再落到"Less structure, more intelligence."
- 可借鉴：任务 chips 作为快速理解产品能力的入口；"Compare VS X" 对比页矩阵；**品牌资产页**（Brand assets）。
- 需规避：Manus 的多 Agent 是黑盒，官网不展示过程——QunWork 反其道而行，过程可视化就是卖点。

**Raycast（raycast.com）——证据型叙事的范本**
- 每个卖点配一个"真的能用"的视觉：键盘大图、扩展商店墙、AI agent 对话实录、证言墙 + 社区人数（Slack 37k）。
- 可借鉴：**"卖点即演示"**原则——蜂群区块不做静态三栏卡片，做一段可交互 DAG 动画；扩展商店墙 → QunWork 的"25+ 连接器 + 技能市场"墙。

### 4.2 综合结论：QunWork 官网 = OpenWorker 的信任结构 × Raycast 的证据叙事 × 蜂群可视化

| 维度 | OpenWorker | Claude | Manus | Raycast | **QunWork 方案** |
|---|---|---|---|---|---|
| Hero 类型 | 主张+下载 | 品牌主张 | 任务输入框 | 主张+键盘视觉 | **主张+蜂群 DAG 动画** |
| 核心证据 | 情景卡+审批门 | 产品截图 | 任务 chips | 真实交互视觉 | **情景卡+DAG+审批门** |
| 下载入口位置 | hero 双按钮 | 导航+hero | 导航 | 导航+hero | **导航常驻+hero+悬浮条** |
| 定价 | 无 | 首页定价 | 独立页 | 独立页 | P0 免费声明，P1 独立页 |
| 开源表达 | 徽章 | 无 | 无 | 无 | **独立区块+仓库直达** |

### 4.3 v1.0 方案遗漏、产品已实现的能力（补入叙事与页面）

v1.0 的蜂群叙事只写到 planner / executor / reviewer / 治理回路，实际产品里还有一批更"硬"的差异化能力没有进入方案。以下每一条都有代码对应，可直接产出官网素材：

| 能力 | 产品实况 | 建议落位 |
|---|---|---|
| **QunMesh 信息素网格** | 四信道信息素（StigmergyBus）驱动动态批量领取；`mesh_claim` / `mesh_domains` / `mesh_topology` 事件实时下发；无信息素/单任务时逐级退化安全 | S5 加强视觉 + /swarm 页 deep-dive（"蜂群"一词的技术注脚） |
| **7×24 长程收敛遥测** | LoopCoop 收敛曲线（谱隙 / 理论轮数 / 收敛过程）+ 分形降级轨迹，随 run 快照持久化，产品内已有可视化组件 | S5 右栏或 /swarm 页（"看得见的收敛"现成视觉） |
| **决策回放时间轴（影子模式）** | 每个 worker 的工具选择 / 权限 / scope / 审批落成可拖动回放的决策轨迹，蜂群与主会话共用同一组件 | /security 合规证据 + /swarm 页 |
| **治理指标真实数值** | 粘度 / 漂移 / **自主率** 三个数值 + 阈值随事件下发；**红线是布尔跳闸** | S5 指标卡（口径已可确认） |
| **命令甲板** | 暂停 / 恢复 · 注入操作员消息 · fork 子任务 · 任务改派 · requeue 审批 | S4 四步条第 3 步可升级为"可干预"演示 |
| **经验库 / 模板 / 分支对比 / Dissolve** | 蜂群经验按 workspace 隔离、任务模板存档"分解策略+验收标准"、fork 分支 A/B 对比、任务组生命周期 | S8 资产沉淀闭环（比"飞轮四步"更具体） |
| **协同报告 + 脱敏导出** | 报告含计划表/逐任务评审与置信度/思维链节选/产出节选/治理表；一键导出脱敏样例（路径、家目录、邮箱、URL 凭据、疑似密钥全部打码） | /swarm 页"协同报告样例（脱敏）"的直接来源；亦可作为 S9 开源区块的"可验证"素材 |

**叙事层建议**：把"蜂群"从"多 Agent 并行"升级为 **"信息素协作 + 治理回路 + 可回放决策"** 三层结构 —— 这三层在竞品官网（OpenWorker 单 Agent 情景卡 / Manus 黑盒多 Agent）都没有对应物，是 QunWork 最不容易被抄走的叙事。

### 8.2 字体与排版阶梯

- 中文：系统栈 `"PingFang SC", "Microsoft YaHei UI", "Noto Sans SC", sans-serif`；西文与数字：**Manrope**（700 用标题，400/500 用正文；woff2 自托管，`font-display: swap`）。品牌锁版内"群沃客"用系统黑体加 0.02em 字距即可，避免引入额外字体包。
- 阶梯：H1 56/64 · H2 40/48 · H3 24/32 · 正文 16/28 · 辅助 14/22 · 标注 12/18；标题字重 700，正文字重 400，按钮 500。
- 段落宽 `max-width: 46ch`；区块垂直节奏 `clamp(72px, 10vw, 128px)`。

### 8.3 形状与质感

- 圆角：卡片 12px、按钮 8px、徽章 999px（与产品内卡片观感一致）。
- 描边优先于阴影：`1px solid var(--line)`，hover 升级为 `0 3px 10px rgba(0,0,0,.08)`（暗色 `.35`）——直接沿用产品任务卡的 hover 语言。
- 不使用渐变彩底与玻璃拟态大面积铺陈；深色区块（S5）是全站唯一的沉浸底，制造节奏。

### 8.4 图形语言

- 图标：线性图标 1.5px 描边，24px 栅格，语义色仅用于状态（在线 ok-dot、待批准 warn）。
- 蜂巢母题：六角形单元作为 S5 区块与 404 页的装饰纹理（低对比描边，透明度 ≤ 8%），呼应"蜂群"品牌；不做成廉价背景墙。
- 产品截图：一律用 1440×900 浅色 + 深色两套，带 16px 圆角与 1px 描边，配 `alt` 描述任务内容；避免拼接假截图——有 SwarmView 真实界面后全部替换 mock。

### 8.5 动效

- 时长 200-350ms，缓动 `cubic-bezier(.2,.7,.3,1)`；DAG 节点状态变化用 300ms 填充过渡。
- 全站尊重 `prefers-reduced-motion`（降级为静态终帧）；视差与跑马灯禁用。

## 十、技术方案

| 项 | 选型 | 理由 |
|---|---|---|
| 框架 | Astro 5（静态输出， islands 按需 hydrate） | 内容站为主，天然 SEO；与产品 React 技术栈同源，组件可迁移 |

| 文档 | VitePress（/docs 子站） | 中文搜索好，维护成本低 |
| 部署 | Cloudflare Pages（海外）+ 备选国内 CDN；`qunwork.com` 主域，`www` 301 | 边缘缓存、免运维 |
| 性能预算 | LCP ≤ 2.0s（4G）、CLS < 0.05、JS ≤ 90KB（首屏路由）、图片 AVIF/WebP | 达标门禁进 CI（Lighthouse CI ≥ 95） |
| SEO | 每页 title/description/OG 图（模板自动生成）、sitemap、JSON-LD（SoftwareApplication + FAQPage）、`lang=zh-CN` | "QunWork/群沃客/AI 同事/蜂群"为核心词 |
| i18n | 路由前缀 `/en`，文案走命名空间 JSON（与产品 messages 同源词表） | 单源维护 |
| 埋点 | 自托管 Plausible（无 cookie，符合本地优先人设） | 不上重型统计 |
| CI | GitHub Actions：构建 + Lighthouse CI + 链接检查 + 链接产品版本号自动同步 | 版本号/下载链接与仓库 Release 联动 |
