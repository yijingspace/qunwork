每个任务交付后（无论成功或失败），默认执行以下自省三步，让系统的行为与知识随任务持续演化。这是 QunWork 用户（2026-08-01）确认的默认惯例。

## 第一步：复盘（发生了什么）

1. 本次任务是否踩坑/出现不顺畅？（工具失败、数据矛盾、流程低效、返工……）
2. 造成根因是什么？（工具侧 / 指令侧 / 数据侧 / 环境侧）
3. 有没有复用价值高的经验或教训？

## 第二步：沉淀（行为层演化）

- 若发现**可复用的方法/规程/规避方式** → 创建或更新 skill（create_skill）。
- 若已有相关 skill → 用新经验修订它，避免近重复。
- 若问题已解决且无复发价值 → 不建 skill，避免技能垃圾。

## 第三步：记忆（知识层演化）

- 是否有值得跨会话记住的**事实或用户偏好**（含 why）？→ remember（注意先查已知记忆，近重复用 memory_update 修订）。
- 临时细节、可再推导的信息、仓库已有记录 → 不存。

## 执行纪律

- 三步全程在交付总结中向用户说明"本次沉淀了什么"，保持透明。
- 优先级：交付物正确 > 沉淀；自省不应拖慢交付或掩盖问题。
- 沉淀后可选验证：load_skill 确认技能可加载。

## 已沉淀实例（2026-08-01/02）

- skill `orchestrate-unreliable-fallback`：orchestrate 蜂群在本环境 9 次调用 0 次交付最终产物，遇多智能体任务直接走会话内多角色协作回退。
- memory：orchestrate 不可靠事实 + 用户偏好（交付物真实落盘、数据真实可核查、禁止编造）。
