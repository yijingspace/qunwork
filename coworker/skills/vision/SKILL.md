# Image Understanding(识图)

文本模型没有视觉。本技能通过本地 OCR + 元数据(可选:视觉模型 API)让模型"看见"图片。

## 何时使用

- 用户上传了图片(上下文会出现 `[image: <绝对路径>]` 标记)
- 用户要求"看这张图 / 截图里写了什么 / 识别图中文字 / 分析这张图片"
- 任务涉及截图、扫描件、照片、图表、UI 界面图

## 步骤

1. 从上下文或用户输入中找到图片路径(通常是 `[image: ...]` 标记里的绝对路径,或用户给出的文件路径)。
2. 运行分析脚本(优先用当前 Python 解释器,保证依赖可用):

```bash
python "<skill 目录>/resources/vision_analyze.py" "<图片路径>"
```

   - 支持多个路径:空格分隔逐个传入;也支持传目录(分析目录下所有图片)。
3. 读取 JSON 输出,按需回答:
   - `metadata`:尺寸 / 格式 / 模式 / EXIF 拍摄时间
   - `ocr.text`:识别出的全部文字(带行坐标)。**回答图中文字问题时以此为准,不要编造。**
   - `vision`:若配置了视觉模型 API 且调用成功,这是模型的语义描述(图中有什么物体/场景/内容)。未配置则为 null——此时不要假装能"看懂"画面,只汇报 OCR 文字与元数据,并如实说明"没有配置视觉模型,只能提取文字与基本信息"。
4. 若脚本报错(如路径不存在),先确认路径,不要臆测图片内容。

## 配置(可选增强:语义理解)

环境变量(可在系统环境或应用配置中设置):

- `VISION_VL_BASE_URL` — OpenAI 兼容视觉模型端点,如 `https://open.bigmodel.cn/api/paas/v4/`(智谱)或 DashScope compatible-mode 端点
- `VISION_VL_API_KEY` — 对应 API Key
- `VISION_VL_MODEL` — 模型名,如 `glm-4v-flash`、`qwen-vl-plus`

配置后脚本会自动把图片(base64)发给该模型做语义描述;未配置时仅 OCR + 元数据,完全本地、无需联网。

## 注意

- OCR 结果对印刷体/清晰截图准确率高;手写体或模糊图片可能出错,汇报时注明置信度低的部分。
- 不要用文本模型"猜测"图片视觉内容(颜色布局等除外,元数据可提供尺寸/格式)。视觉内容必须来自 OCR 或视觉模型输出。
